## 1. 测试目标

### 1.1 核心目标

1. **验证 P0 功能可用性** - 确保 MVP 核心功能满足用户需求
2. **发现 usability 问题** - 识别用户体验中的痛点和困惑
3. **收集性能反馈** - 验证性能指标在真实使用场景中的表现
4. **优先修复关键问题** - 基于用户反馈确定修复优先级

### 1.2 测试范围

| 测试模块 | 测试重点 | 参与人员 |
|----------|----------|----------|
| SSH 连接管理 | 创建、编辑、连接稳定性 | 全员 |

| 会话管理 | 多标签、切换、后台保活 | 全员 |
| 密钥管理 | 导入、生成、生物识别 | 技术背景人员 |

## 4. 问题优先级排序

### 4.1 优先级定义

| 优先级 | 名称 | 定义 | 响应时间 | 修复时限 |
|--------|------|------|----------|----------|
| P0 | Critical | 崩溃、数据丢失、安全漏洞、核心功能不可用 | 立即 | 24 小时 |
| P1 | High | 主要功能有缺陷，影响大部分用户 | 4 小时 | 3 天 |
| P2 | Medium | 功能有缺陷但有 workaround，影响部分用户 | 1 天 | 1 周 |
| P3 | Low | 体验问题、UI 瑕疵，不影响功能使用 | 3 天 | 2 周 |

### 4.2 优先级评估矩阵

| 用户影响 ⧸ 频率 | 必现 (>80%) | 经常 (50-80%) | 偶尔 (20-50%) | 罕见 (<20%) |
|----------------|------------|--------------|--------------|------------|
| **严重影响** | P0 | P0 | P1 | P2 |
| **中度影响** | P1 | P1 | P2 | P3 |
| **轻微影响** | P2 | P2 | P3 | P3 |

### 4.3 问题追踪流程

```
问题发现 → 提交反馈 → 初步评估 → 优先级定级 → 分配修复 → 修复验证 → 关闭问题
    │           │           │           │           │           │
    ▼           ▼           ▼           ▼           ▼           ▼
 测试群      飞书问卷    产品经理    技术负责人   开发工程师   测试工程师
```
