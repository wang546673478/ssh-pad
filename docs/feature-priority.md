## 优先级定义

### 优先级分级

| 级别 | 名称 | 说明 | 阶段 |
|------|------|------|------|
| P0 | Must Have | 必须有，MVP 核心功能 | Week 5-10 |
| P1 | Should Have | 应该有，重要功能 | Week 11-14 |
| P2 | Nice to Have | 可以有，增值功能 | Week 15+ |
| P3 | Future | 未来考虑，长期规划 | 后续版本 |

### 优先级评估维度

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 用户价值 | 40% | 高 (5) / 中 (3) / 低 (1) |
| 使用频率 | 30% | 高频 (5) / 中频 (3) / 低频 (1) |
| 技术难度 | 20% | 低 (5) / 中 (3) / 高 (1) |
| 商业价值 | 10% | 高 (5) / 中 (3) / 低 (1) |

## 功能砍掉清单

| 功能 | 原因 | 备注 |
|------|------|------|
| Telnet 支持 | 需求极低、安全风险 | 如有需求再议 |
| Serial 串口 | 偏离核心场景 | - |
| RDP/VNC远程桌面 | 复杂度高、非核心 | 长期规划 |
| 内建聊天功能 | 伪需求 | - |
| 社交功能 | 偏离工具定位 | - |

## 附录：优先级评分卡

### 评分模板

```
功能名称：XXX

用户价值 (40%): [1-5] 分
  - 解决什么痛点？
  - 多少用户需要？

使用频率 (30%): [1-5] 分
  - 每天/每周/每月使用次数？

技术难度 (20%): [1-5] 分
  - 开发工时估算
  - 技术风险

商业价值 (10%): [1-5] 分
  - 是否可付费？
  - 是否差异化？

综合得分 = 用户价值*0.4 + 使用频率*0.3 + 技术难度*0.2 + 商业价值*0.1
```
